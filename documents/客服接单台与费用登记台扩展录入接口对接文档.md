## 1. 公共约定与状态

- 根路径为 `/api/v1`，本文所有HTTP调用路径均已包含该前缀；环境域名由部署环境决定。
- 所有接口需要 `Authorization: Bearer <access_token>`，账号须启用。JSON写入请求带 `Content-Type: application/json`。
- GET无请求体。保存/暂存的请求体是下文业务对象，不能再包一层 `data`。
- JSON成功响应HTTP 200，结构为 `{ "code": 0, "data": ..., "msg": "..." }`；Excel成功返回文件二进制。
- 所有返回主键为字符串。JavaScript应始终按string保存和传递，禁止先转number造成大整数精度丢失。
- `id` / 路径参数 `consignment_id` 是数字字符串主键；`internal_doc_id` 是前端提供的业务编号，两者用途不同。
- 写入接口没有新增URL，扩展的是既有请求/响应字段与客服状态校验。业务可写字段均为可选；前端可按业务另做必填提示。

| status（返回number） | 含义 | 客服保存/暂存 | 费用保存/暂存 |
|---|---|---|---|
| 0 | 未提交 | editable=true时允许；费用曾保存锁定后不可编辑 | 允许 |
| 1 | 已提交 | 客服仅保存仍可编辑；费用保存后editable=false，两种修改接口均409 | 仍可维护，暂存不解除客服锁定 |
| 2 | 作废 | 两种修改接口均409 | 两种修改接口均409 |

2026-11-09更新：客服保存成功后仍可编辑，费用保存提交成功后才锁定客服。前端使用客服响应的editable控制编辑/暂存/保存，不能只看status；费用后续暂存不解锁。完整契约见第20节。
锁定限制字段修改与退回暂存，不代表原有作废、删除、查询、下载入口被取消。
“登记编辑区唯一模板”和“列表单据”是两类数据，修改模板不会修改或解锁已提交列表单据。

### 1.1 所有详情/修改/暂存/作废接口共用的路径参数

| 参数 | 位置 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| `consignment_id` | Path | string | 是 | 对应台列表或写入接口返回的id，使用数字字符串；不要使用internal_doc_id |
| `Authorization` | Header | string | 是 | Bearer加空格及access_token |
| `Content-Type` | Header | string | 有JSON请求体时 | application/json |

例如 `PUT /api/v1/customer-service/consignments/358000000000000001/draft` 的路径参数是字符串 `358000000000000001`。
响应包裹层：`code`为integer（成功0，失败为对应错误码），`data`为业务对象/分页对象/null，`msg`为string提示文本。

## 2. 受影响接口总表

完整客服业务响应对象下文称S，完整费用业务响应对象称C；S、C都是 `data` 内对象，不是额外JSON键。
它们的完整可复制JSON分别见第5、6节。总表列出本需求20个受影响接口，路径和请求体包裹层级不变。

| 方法 | 路径 | 本次入参变化 | 成功响应 data / 副作用 |
|---|---|---|---|
| GET | `/api/v1/customer-service/consignment-registration` | 无 | S；无模板时仍为 null |
| PUT | `/api/v1/customer-service/consignment-registration` | 客服请求结构 S 的业务字段，新增两个分组 | S；更新唯一模板，不流转 |
| POST | `/api/v1/customer-service/consignments` | 客服请求结构，新增两个分组 | S，status=1；同事务同步费用 C，费用 status=0 |
| POST | `/api/v1/customer-service/consignments/draft` | 同客服新增 | S，status=0；只写客服 |
| GET | `/api/v1/customer-service/consignments` | 查询条件不变 | `{items:[S],total,page,pageSize}`；每条增加两个分组 |
| GET | `/api/v1/customer-service/consignments/{consignment_id}` | 无 | S，增加两个分组 |
| PUT | `/api/v1/customer-service/consignments/{consignment_id}` | 同客服请求，可只传变更字段；仅 editable=true 可执行 | S，status=1、editable=true；同步费用status=0；费用提交锁定或作废返回409 |
| PUT | `/api/v1/customer-service/consignments/{consignment_id}/draft` | 同上；仅 editable=true 可执行 | S，status=0、editable=true；不写费用；费用提交锁定或作废返回409 |
| PUT | `/api/v1/customer-service/consignments/{consignment_id}/void` | 无请求体 | S，status=2；新增分组随业务数据保留 |
| POST | `/api/v1/customer-service/consignments/export-excel` | `{ids:[string]}` 不变 | xlsx 二进制；94列，单行表头，第2行开始为数据 |
| GET | `/api/v1/cost-service/cost-registration` | 无 | C；无模板时仍为 null |
| PUT | `/api/v1/cost-service/cost-registration` | 既有费用请求增加20个叶字段 | C；只更新模板 |
| POST | `/api/v1/cost-service/consignments` | 同费用请求 | C，status=1；回写客服基本信息及应收/应付快照，客服锁定 |
| POST | `/api/v1/cost-service/consignments/draft` | 同费用请求 | C，status=0；不创建客服记录 |
| GET | `/api/v1/cost-service/consignments` | 查询条件不变 | `{items:[C],total,page,pageSize}`；每条补齐新增字段 |
| GET | `/api/v1/cost-service/consignments/{consignment_id}` | 无 | C，补齐新增字段 |
| PUT | `/api/v1/cost-service/consignments/{consignment_id}` | 同费用请求，可只传变更字段 | C，status=1；回写客服基本信息及应收/应付快照 |
| PUT | `/api/v1/cost-service/consignments/{consignment_id}/draft` | 同费用请求 | C，status=0；不回写客服，也不改变客服现有editable（费用曾保存后不会解锁） |
| PUT | `/api/v1/cost-service/consignments/{consignment_id}/void` | 无请求体 | C，status=2；新增业务字段保留 |
| POST | `/api/v1/cost-service/consignments/export-excel` | `{ids:[string]}` 不变 | xlsx 二进制；118列，单行表头，第2行开始为数据 |

列表、详情、作废和模板查询也列入本表，因为其返回业务对象补齐了新字段。详情无新增参数。
后续编号需求额外扩展的两个操作记录GET接口见第12节；单个/批量删除的原有调用结构保持不变，不需为本次财务字段另传参数。

汽运主单号和城市应控制在100字符以内；长度为数据库限制，不表示接口一定在请求阶段用422拦截超长值。

### 3.3 全部可写业务字段

以下表内字段**全部可选、均接受null**；每行示例仅说明该字段，不代表所有示例必须同时提交。“可null”不等于“null一定清空”，不同台/新旧字段的处理规则见第4节。
财务字段行中“新增20字段=是”的项使用新增字段的空值规则；“否”表示沿用既有费用字段规则。客服财务字段统一按客服快照规则。
日期使用 `YYYY-MM-DD`；制单时间使用 `YYYY-MM-DD HH:MM:SS`。不要把业务日期与只读创建/更新时间混用。

## 4. 省略、null和同步规则

### 4.1 写入与清空

| 数据范围 | 字段省略 | 字段显式null | 传0或空字符串 |
|---|---|---|---|
| 客服 `receivables` / `payables` 分组及子对象 | 保留旧分组 | 整个分组null也保留 | `{}`不清空 |
| 客服财务分组中的叶字段 | 保留旧值 | 清空该叶字段 | 数值0保存，字符串空串保存；数值字段空串422 |
| 客服列表单据顶层数值（pieces、actual_weight、chargeable_weight、volume、first_leg_weight）修改 | 保留 | 清空 | 0有效 |
| 客服列表单据顶层文本/日期修改 | 保留 | 保留 | 文本空串保存；日期请按规定格式发送 |
| 客服唯一登记模板的原顶层基本信息 | 按完整保存处理，可清空未传字段 | 按完整保存处理 | 不要把单据局部更新规则直接用于模板；新财务分组仍按上方合并规则 |
| 费用新增20个叶字段 | 保留旧值 | 清空该叶字段 | 0或字符串空串保存，数值空串422 |
| 费用旧字段及折让、提成金额、经营信息 | 保留旧值 | 保留旧值 | 0可覆盖数值；文本空串保存 |
| 两台标签字段 | 保留 | 保留 | `[]`清空 |

新建时没有可保留旧值的字段通常为空；不要把“省略”解释成自动计算/自动复制所有费用字段。
费用旧字段目前不支持通过null清空已有金额；如页面需要该能力，应另行约定，不能假定与新增20字段一致。

局部修改客服草稿示例：

```json
{
  "receivables": {
    "fuel_rate": 0,
    "remark": null
  },
  "payables": {
    "ground": {
      "tc_fee": null
    }
  }
}
```

此请求仅修改草稿中的这三个叶字段；其余财务值保留。若发往费用修改接口，`tc_fee`是旧字段，null会保留旧金额。

### 4.2 提交同步与锁定

1. 客服暂存新增/暂存修改：客服status=0，只写客服；费用台不创建或更新。
2. 客服保存新增/草稿提交：客服status=1、editable=true，允许再次编辑；同ID费用单据基础信息及明确录入财务字段同步，费用status=0。
3. 同步先写基本信息，再预填国际空运的件数、实际重量、航班日期、计费重量、航班号、体积、主单号，再用客服明确填写过的应收/应付叶字段覆盖。航班号按第26节的新联动规则：本次填写委托航班号时，先同步本台国际空运快照，同次请求以委托航班号为准；其他预填字段保持原规则。
4. 例如客服顶层actual_weight=100，intl_air.weight=105，费用基本信息重量为100，国际空运重量为105。此前草稿已填写的字段也算明确录入；显式null仍有清空效力。
5. 费用保存：费用status=1，回写同ID客服基本信息及应收/应付快照，客服status=1、editable=false，此时锁定；费用独有折让/提成/经营分组不写入客服请求结构。
6. 费用暂存：费用status=0，仅保存费用侧数据；不会把客服状态改回0，客服已被费用保存锁定时不解除，尚未锁定时仍可编辑。
7. 两台均保存customer_tags和expense_tags。客服提交时按同名字段复制非null数组（含[]）到费用；费用可分别覆盖/清空，费用保存不反向改写既有客服标签。标签不决定是否存储某个金额分组。
8. 保存、同步和操作记录共用事务；客服修改使用行锁后检查状态。客户端重复调用新增不会自动去重，应避免重复创建。

### 4.3 前端计算与旧记录显示

报关组合数量解析、报关费、燃油费、TC费、前置仓费、运费、小计、应收应付合计、折让、提成金额、利润/利润率均由前端处理并传值；后端不按Excel示例公式重新计算。
例：提交fuel_rate=0和receivable_fuel_fee=65仍可保存65，不会自动改成0；所以修改费率时若希望修改金额，需一起提交计算后的金额。
旧客服记录无财务快照时，查询返回已知分组对象及叶字段null，不自动从费用记录反推费率；费用后续保存会回写快照。
费用旧文本可能返回空字符串，新20字段空值通常为null。控件需兼容null、空串、数值0，金额0不能用 `value || ''` 错误显示成空值。

## 9. 列表查询参数与返回说明

### 9.1 公共查询参数

| 参数 | 位置 | 类型 | 必填 | 默认/含义 |
|---|---|---|---|---|
| `status` | Query | integer | 否 | 0未提交/1已提交/2作废，不传全部 |
| `customer_name` | Query | string | 否 | 客户名称模糊匹配 |
| `sort_by` | Query | string | 否 | create_time或warehouse_entry_date；客服默认create_time，费用默认warehouse_entry_date |
| `sort_order` | Query | string | 否 | asc或desc，默认desc |
| `page` | Query | integer | 否 | 默认1，最小1 |
| `pageSize` | Query | integer | 否 | 默认10，最小1；列表当前未设最大值，与操作记录分页上限不同 |

### 9.2 客服列表额外查询参数

`GET /api/v1/customer-service/consignments`

| 参数 | 类型 | 必填 | 含义 |
|---|---|---|---|
| `start_date` | string | 否 | 制单日期开始，YYYY-MM-DD，含当天 |
| `end_date` | string | 否 | 制单日期结束，YYYY-MM-DD，含当天 |
| `destination` | string | 否 | 模糊匹配origin_destination最后一个“-”之后的目的站 |
| `flight_no` | string | 否 | 仅模糊匹配客服自身航班号 |
| `flight_doc_no` | string | 否 | 主单号，仅模糊匹配客服委托信息顶层flight_doc_no；首尾空白去除，空值不筛选，详见第22节 |

### 9.3 费用列表额外查询参数

`GET /api/v1/cost-service/consignments`

| 参数 | 类型 | 必填 | 含义 |
|---|---|---|---|
| `start_warehouse_date` | string | 否 | 进仓日期开始，YYYY-MM-DD |
| `end_warehouse_date` | string | 否 | 进仓日期结束，YYYY-MM-DD |

| `agent` | string | 否 | 货主委托信息代理字段模糊匹配 |
| `flight_doc_no` | string | 否 | 主单号，仅模糊匹配国际空运 `payables.intl_air.flight_doc_no`，首尾空白去除，空值不筛选；详见第17节 |
| `flight_no` | string | 否 | 同时匹配货主、国际空运、国内空运航班号 |

日期筛选可只传一端，进仓和航班日期独立组合；建议始终传有效日期，不依赖旧逻辑忽略非法日期的兼容行为。

## 10. Excel下载

### 10.1 接口和入参

- 客服：`POST /api/v1/customer-service/consignments/export-excel`
- 费用：`POST /api/v1/cost-service/consignments/export-excel`

| 参数 | 位置 | 类型 | 必填 | 含义 |
|---|---|---|---|---|
| `ids` | JSON Body | string[] | 是 | 选中单据的数字字符串主键数组，至少选一条；不能传internal_doc_id |

两接口请求示例：

```json

  ]

```

### 10.2 返回与下载处理

成功HTTP 200；返回xlsx文件二进制，**没有code/data/msg JSON包裹**。

```http
Content-Type: application/vnd.openxmlformats-officedocument.spreadsheetml.sheet
Content-Disposition: attachment; filename=consignment_export_20261030100000.xlsx
Access-Control-Expose-Headers: Content-Disposition
```

客服文件名以 `consignment_export_` 开头，费用文件名以 `cost_consignment_export_` 开头（以实际响应头为准）。
前端使用blob下载，同时检查HTTP状态及Content-Type，失败JSON不要作为xlsx保存。业务编号字段继续存储，但不出现在Excel中。

| 台 | 表头 | 总列数 | 数据开始行 | 当前布局 |
|---|---|---|---|---|
| 客服 | 单行 | 94 | 第2行 | A至CP，完整列顺序见第14节 |
| 费用 | 单行 | 118 | 第2行 | A至DN，完整列顺序见第14节 |

2026-11-01按客户新模板重排列顺序、2026-11-02补充汽运计算方式：两台均A列序号、B列状态，无合并表头，无空白占位列；内部编号继续不导出。费用两个应收合计及五个应付小计按指定位置保留，详见第14节。
客服导出按制单时间倒序；费用按货主航班日期升序，空日期最后，同日期按主键升序，不直接使用页面列表排序。
状态转中文未提交/已提交/作废；提单按既有规则转中文；费用应收运费计算方式1/2转实际重量/计费重量，汽运计算方式原样导出，其他取重方式不再导出；金额0导出为数值0，null为空单元格，不写公式。
不存在的ids不输出记录，没有任何匹配记录仍可返回仅表头文件；不要用此行为替代前端至少选一条校验。

### 10.3 前端调用示例

```javascript
async function downloadSelected(baseURL, token, ids, desk) {
  const response = await fetch(`${baseURL}/api/v1/${desk}/consignments/export-excel`, {
    method: 'POST',
    headers: { Authorization: `Bearer ${token}`, 'Content-Type': 'application/json' },
    body: JSON.stringify({ ids }),
  });
  const contentType = response.headers.get('Content-Type') || '';
  if (!response.ok || !contentType.includes('spreadsheetml.sheet')) {
    const error = await response.json();
    throw new Error(error.msg || '下载失败');
  }
  const blob = await response.blob();
  const disposition = response.headers.get('Content-Disposition') || '';
  const filename = disposition.match(/filename="?([^";]+)"?/)?.[1] || '委托费用.xlsx';
  const objectURL = URL.createObjectURL(blob);
  const a = document.createElement('a');
  a.href = objectURL;
  a.download = filename;
  document.body.appendChild(a);
  a.click();
  a.remove();
  setTimeout(() => URL.revokeObjectURL(objectURL), 1000);
}
// desk为'customer-service'或'cost-service'；ids始终为string[]。
```

## 12. 勾选项和内部编号兼容约定

这些为后续已确认需求，当前同一版本的完整请求/响应示例已包含对应字段。

### 12.1 标签无需单独新增保存接口

两台顶层均支持customer_tags和expense_tags，通过上述新增、保存、暂存、模板PUT保存，并从详情data第一层级同时回显两个数组；列表/写入响应同样返回。

| 字段 | 类型 | 可选值 | 规则 |
|---|---|---|---|
| `customer_tags` | string[]/null | intl_air、customs、ground、trucking、dom_air | 最多5项 |
| `expense_tags` | string[]/null | 上述5项及discount_info、sales_commission | 最多7项 |

intl_air国际空运、customs报关、ground地面操作、trucking汽运、dom_air国内空运、discount_info折让信息、sales_commission销售提成。
省略/null保留原值，[]清空；有效重复项去重，非法值422，超出原数组长度限制也会422。旧记录查询无选择项时返回[]。
客服提交时两个非null数组复制到费用；暂存不流转。费用可覆盖/清空两个字段，不反写既有客服标签；客服提交后标签同样不可修改。两个字段不相互重命名，不把customer_tags自动当成expense_tags。取消勾选不自动清除对应财务字段。

## 14. Excel完整导出契约（2026-11-02更新）

两个现有导出接口仅调整下载文件的表头、列顺序与取值范围，不新增路由。2026-11-01改为单行表头；2026-11-02两台汽运分组补充“运费计算方式”；2026-11-09委托信息区在进仓日期后恢复“航班日期”；2026-11-11应收耗材费后增加“一程费用”，当前契约如下。

| 方法 | 完整接口路径 | 总列数 | 表头行 | 首条数据行 |
|---|---|---|---|---|
| POST | `/api/v1/customer-service/consignments/export-excel` | 94（A至CP） | 第1行 | 第2行 |
| POST | `/api/v1/cost-service/consignments/export-excel` | 118（A至DN） | 第1行 | 第2行 |

**请求**：沿用当前登录认证（`Authorization: Bearer <token>`），`Content-Type: application/json`。两台相同：

```json
{"ids":["358000000000000001","358000000000000002"]}
```

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `ids` | string[] | 是 | 选中的单据主键，前端以数字字符串传递，至少一项；不是内部单据ID。仅导出本台匹配记录，重复ID不会重复输出；不存在的ID忽略。排序不采用请求数组顺序。 |

**成功返回**：HTTP 200，xlsx文件二进制，**没有JSON的code/data/msg包裹**。响应头示例：

```http
Content-Type: application/vnd.openxmlformats-officedocument.spreadsheetml.sheet
Content-Disposition: attachment; filename=consignment_export_20261101100000.xlsx
Access-Control-Expose-Headers: Content-Disposition
```

费用文件名示例为 `cost_consignment_export_20261101100000.xlsx`；实际时间取服务端生成时间。前端继续按blob下载，并先检查HTTP状态和Content-Type。

**文件规则**：

- 两台均第1列“序号”、第2列“状态”。序号按最终导出结果从1连续编号，状态读取本台单据自身的status：0=未提交、1=已提交、2=作废。
- 仅一行表头，无分组标题行、合并单元格或空白占位列，客户表格中的空白项全部忽略。下方表头文字及顺序为完整契约，重复名称按所在列区分。
- 客服排序仍为制单时间 `create_time` 倒序；费用仍按货主航班日期 `consignor_info.flight_date` 升序，空日期最后，同日期按主键ID升序。委托航班日期在第8列（H）展示，费用排序继续使用该字段。

## 15. 两组标签跨台流转补充（2026-10-30）

客服和费用均支持两组标签，采用同名字段复制，customer_tags最多5项、expense_tags最多7项。前端需分别提交两个字段；仅传customer_tags不会自动勾选expense_tags。

客服提交两个字段：

```json
{"customer_tags":["intl_air","customs"],"expense_tags":["ground","discount_info"]}
```

费用详情data第一层同时返回上述数组；费用覆盖可提交：

```json
{"customer_tags":["dom_air"],"expense_tags":[]}
```

覆盖后费用后续查询返回customer_tags=["dom_air"]、expense_tags=[]，客服原始标签不变。无新路由，仍使用现有保存或暂存接口；独立API总文档23.14列有完整接口、字段和返回示例。

## 16. 汽运运费计算方式补充（2026-11-02）

费用汽运新增 `payables.trucking.freight_method`（可选string/null，最多50字符）。前端定义“计费重/体积重”等选项，后端原样保存字符串，既不限定枚举也不规定字符串编码的含义；修改时不传保留、null清空、空字符串原样保存。不重算运费和小计。

```json
{"payables":{"trucking":{"freight_method":"体积重"}}}
```
